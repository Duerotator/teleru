# teleru: перевод и обновления

## Что изменено

Сборка использует `TELE_UPSTREAM.json` как источник версии: опубликованный стабильный релиз `nitreojs/tele`, полный commit SHA и соответствующий тег Telegram Desktop. Подготовка исходников проверяет SHA: переназначенный тег не принимается.

Все workflows запускаются только вручную. Расписания `Sync` и `Canary`, сборка по push и автоматический `Promote` отключены по просьбе владельца. Новая версия tele сама не обновляет исходники teleru и не запускает перевод или сборку.

`Sync` при ручном запуске проверяет релизы **tele**, а не `telegramdesktop/tdesktop`. Он обновляет только файл версии, сохраняет перевод и запускает `Build`. Для новой версии сначала предпочтительно локально выполнить `python ci/upstream.py update`, подготовить исходники и проверить перевод, затем отправить изменения и вручную запустить `Build`. При отключённых Issues уведомление через issue пропускается; ошибка и отчёт остаются в Actions.

`Build` сначала применяет зафиксированную очередь и русский перевод в отдельной проверке. Только успешная проверка разрешает сборку бинарника. Если tele добавит новые подписи или изменит описание настройки, выпуск блокируется: последний рабочий релиз остаётся доступным, а перевод нужно дополнить.

Оригинальные `patches/`, `UPSTREAM` и `tele.py` оставлены как наследованная очередь. Они **не являются источником новой сборки**. Не пытайтесь обновить teleru простым копированием `main` tele или запуском старого `Sync`: так можно заменить собственные файлы форка.

## Каталог перевода

Основные строки находятся в `i18n/ru.json`, новые разделы — в `i18n/ru/*.json`. Для обычной подписи используется точное соответствие английского текста русскому. Для неоднозначных слов есть `contexts`, привязанные к конкретному файлу.

У настроек перевод привязан одновременно к `kOption...` и исходному английскому тексту:

```json
{
  "options": {
    "kOptionExample": {
      "name": {"source": "Example", "translation": "Пример"}
    }
  }
}
```

Если `source` перестал совпадать, перевод нельзя автоматически считать актуальным. Сначала нужно прочитать новый текст, затем обновить обе части записи. Нельзя подставлять новый `source`, не проверив русский перевод.

Проверка охватывает QString-литералы tele, метаданные настроек, добавленные tele строки в исходниках Telegram и ресурсы `Resources/tele_html`. Проверяются экранирование и параметры `%1`, `%2`, `%L1`, `%n`, `%%`. HTML/JavaScript разбираются отдельно; новые шаблонные JavaScript-литералы требуют ручной проверки. Встроенные HTML-страницы и сериализованные меню имеют точные записи в `embedded-ui.json`: изменение шаблона требует повторной проверки.

Идентификаторы настроек, JSON-поля, имена методов, URL, CSS-классы, кодовые примеры и форматы дат не являются обычными переводимыми подписями. Их исключения перечислены явно и привязаны к файлам; новый неизвестный текст не исключается автоматически. Если известный технический токен появляется как новая видимая подпись через `Lower`, исключение не должно скрыть отсутствие перевода.

Процент в отчёте относится к **найденным кандидатам**, а не является доказательством 100% русского текста во всём работающем приложении. Он не включает язык Telegram из его языкового пакета, названия пользовательских данных, ответы серверов, тексты мини-приложений и архивные описания старых релизов tele. В основной части Telegram нужно выбрать русский язык. Переходы новых исходников на другие способы формирования UI-строк требуют расширения проверки.

Встроенный архив tele заменяется краткой русской записью первого выпуска teleru. Это не перевод подробной истории tele: новые записи и кнопки перехода берутся из собственного репозитория teleru; для исходных подробностей остаётся ссылка в описании релиза. Кеш истории также отдельный, чтобы старые записи tele не смешивались с выпусками форка.

## Вычитка с учётом контекста

`i18n/ru/reviewed-settings.json` переопределяет старые формулировки после остальных тематических каталогов. Название и описание сохраняют привязку к исходному английскому тексту: изменение исходника блокирует выпуск, а не незаметно переносит старый перевод.

Вычитка от 2026-10-06 исправляет 141 поле у 113 настроек и 40 связанных строк. Проверялись метаданные настроек, их размещение в `settings_tele.cpp` и реализация спорных функций. Раздел Sending содержит не только отложенные сообщения, поэтому называется «Отправка сообщений»; его группа Scheduled messages остаётся «Отложенные сообщения».

Особое внимание уделяется ограничениям: этому устройству, работающему приложению, исключениям для защищённых чатов, обязательным клавишам и внешним сайтам. Перевод не должен добавлять обещания, которых нет в функции, или заменять условие общим пересказом названия.

Для импортируемых настроек используются три формы слова «настройка» из `plurals.setting`. Наложение заменяет английское добавление `s` минимальным вызовом отдельного `Tele::RussianPluralIndex`, добавляет его заголовок в список исходников tele и сохраняет окончания строк. Если функция склонения, её аргументы или список исходников изменились, сборка останавливается для проверки. Созданный заголовок включается в контрольные суммы наложения.

Стандартный заголовок и пресеты используют «ТЕЛЕ #{build}». Сохранённые точные стандартные шаблоны `TELE #{build}`, `TELE {build}` и `TELERU #{build}` отображаются на русском без изменения пользовательского хранилища. Другие пользовательские шаблоны сохраняются как есть. Переменная `{build}` и знак `#` остаются частью шаблона; новый заголовок включён в проверку целостности наложения.

## Автоматический перевод новых строк

Автоперевод технически возможен, но пока не подключён: отсутствует выбранный переводчик и его API-доступ. Текущая сборка продолжает блокировать непереведённые строки. Проверять нужно новые и изменённые тексты, а не предполагать, что каждый номер релиза обязательно добавляет настройки.

По текущему выбору владельца новые строки переводятся и проверяются только после его сообщения. Далее вручную запускается сборка. API-переводчик, периодические проверки и автоматическое принятие перевода не подключаются. Следующий процесс остаётся возможным вариантом на будущее, а не включённой автоматизацией:

1. Из `localization-report.json` и инвентаризации собрать новые строки и изменения метаданных по `kOption...`.
2. Передать переводчику вместе название и описание, страницу и группу настройки, место использования, условия в функции и предыдущий перевод. Для короткого слова вроде Sending этого контекста больше, чем словарного значения.
3. Использовать единый словарь: «Отложенные сообщения», «Отправка сообщений», «Снимок сообщения», «звёзды», «режим невидимки», «расширенное сообщение», «уведомления», «на этом устройстве». Расширенное сообщение здесь означает формат `Iv::RichPage`, а не обычное сообщение с жирным текстом.
4. Сохранять результат отдельно от `i18n/ru/*.json`, например в `.local/translation-drafts/`. Все JSON в `i18n/ru` применяются автоматически, поэтому неподтверждённый черновик нельзя помещать туда.
5. Проверить параметры, разметку, технические токены, формы числа и покрытие, затем отдельно проверить смысл отрицаний, ограничений и сетевых действий.
6. После проверки внести перевод в каталог и повторить обычную сборку. Полностью автоматическую публикацию нельзя считать гарантией смысловой точности даже после второго машинного рецензента.

API должен получать только публичные строки и необходимый контекст исходников. `tdata`, аккаунты, переписка, логи, `.env`, токены и ключи подписи туда не отправляются. Ключ переводчика хранится в GitHub Secrets, а недоступность API не разрешает выпуск непроверенного перевода. Перед подключением нужно выбрать сервис, лимит затрат и режим подтверждения; исходный каталог и подписывающий ключ остаются независимыми от переводчика.

## Подготовка первого выпуска

1. Перенесите изменения в основную ветку своего GitHub-репозитория. Локальная работа сама ничего не публикует.
2. `TDESKTOP_API_ID` и `TDESKTOP_API_HASH` работают как раньше: при наличии используются Secrets, иначе — прежние значения из конфигурации сборки. Добавлять эти Secrets для запуска сборки необязательно.
3. Добавьте Secret `TELE_UPDATE_KEY`: содержимое приватного PEM-ключа из `.local/update-private-key.pem` в этой локальной рабочей папке. Не добавляйте файл в Git, не публикуйте его в issue и не выводите в лог. Сохраните отдельную защищённую резервную копию.
4. Публичная часть уже находится в `ci/update-public-key.pem`; она встраивается в клиент. Перед сборкой проверяется соответствие Secret этому ключу.
5. В Actions запустите `Build` вручную: `platforms=windows`, `publish=false`. Расписания включать не нужно.
6. Проверьте бинарник по списку ниже. После успешной проверки повторите с `publish=true` либо используйте `from_run` для публикации проверенных артефактов. `from_run` требует полного совпадения исходников, каталога, ключа и конфигурации сборки.

Повторный запуск генерации ключа не нужен. Если поменять публичный ключ после выпуска клиентов, они не смогут проверять новые обновления без отдельной миграции.

## Подписанные обновления и старые клиенты

Новый клиент читает `teleru-update-win64.json` (аналогично Linux/macOS), проверяет Ed25519-подпись, адрес релиза в своём репозитории и хеши архива/исполняемого файла. Проверка подписи не отключается.

Старый выпущенный teleru использовал публичный ключ tele и разрешал пустую подпись. Поэтому отдельно создаётся совместимый `tele-update-*.json` без подписи, **только для перехода старого клиента** на новый бинарник с собственным ключом. Это наследованный небезопасный канал: для первого обновления предпочтительнее скачать новый релиз вручную из своего репозитория. Новые клиенты этот файл не используют.

## Локальные команды

Нужны Python 3.11+, Node.js и Git. Исходники Telegram — отдельный чистый checkout с рекурсивными подмодулями на теге, который выводит первая команда.

```powershell
python ci/upstream.py version
npm ci --prefix ci --ignore-scripts
python -m pip install -r ci/requirements.txt
python -m unittest discover -s ci/tests -v
python ci/upstream.py apply --tdesktop C:\path\to\tdesktop
python ci/translate_ru.py C:\path\to\tdesktop --inventory localization-inventory.json
```

При ошибке смотрите `localization-report.json`: `missing` содержит путь, строку и исходный текст, `invalid` — нарушенные параметры. При успешном повторном запуске того же наложения проверяются контрольные суммы ранее изменённых файлов. Если каталог или исходники изменились, нужен свежий checkout: поверх уже русского текста обновлённый перевод не накладывается.

## Проверка собранного приложения

- Все страницы настроек tele, названия групп, выбор значений и поиск.
- Контекстные меню сообщения, чата, списка чатов, папок, профиля, редактора и отправки; вложенные группы и редактор меню.
- Подарки, студия подарков, сетка, черновики, сохранённые сообщения, скрытый режим, снимки, экспорт настроек.
- MTProto-консоль: режимы, справка, подсказки, ошибки, отправка/отмена, история. Инспектор: фильтры, журналы, подтверждения и просмотр записи.
- Страница браузерного веб-прокси, состояния подключения и счётчики.
- После перезапуска: сохранённые значения настроек, шаблоны заголовка и сохранённые меню работают без изменений.
- Обновление старого teleru на новую сборку и затем обновление между двумя подписанными сборками; изменённая подпись или повреждённый архив отклоняется.

Опубликованная Windows-сборка `v7.2.9-tele.2` была установлена и проверена на нескольких страницах настроек. Последующие изменения каталога и наложения требуют новой сборки и ручной проверки её интерфейса. Проверка исходников и тесты не заменяют полную сборку Qt/C++ или проверку всех экранов.
