# teleru: архитектура локализации и обновлений

`teleru` — это полностью локализованная на русский язык сборка клиента [tele](https://github.com/nitreojs/tele) (форка Telegram Desktop), включающая синхронизацию с актуальными выпусками upstream, расширенные настройки, сохранение терминологической целостности и систему подписанных обновлений.

---

## Архитектура и принципы синхронизации

1. **Единый источник версии (`TELE_UPSTREAM.json`)**:
   - Сборка жестко привязана к опубликованному upstream-релизу `nitreojs/tele`, конкретному полному SHA коммита и базовому тегу Telegram Desktop (например, `v7.3.1`).
   - При подготовке исходников валидируется точный SHA коммита: переназначение тегов или непреднамеренный дрейф кода не допускаются.

2. **Защита от непроверенных сборок (Fail-Closed Pipeline)**:
   - Сборки запускаются вручную через `workflow_dispatch` в GitHub Actions. Это исключает публикацию случайных изменений и гарантирует, что каждый релиз проходит аудит.
   - Шаг `Build` в CI сначала применяет зафиксированную очередь патчей upstream и каталог русского перевода, проводя аудит 100% кандидатов на перевод.
   - Если в upstream появляются новые строки интерфейса, новые настройки `kOption...` или изменяются описания существующих опций, сборка автоматически блокируется с подробным отчетом (`localization-report.json`).

3. **Очередь патчей upstream**:
   - Оригинальные патчи upstream применяются на чистые исходники Telegram Desktop через `ci/upstream.py apply`.
   - Наложение перевода и системных адаптаций (`ci/translate_ru.py`) происходит поверх пропатченного кода с контролем хешей каждого измененного файла.

## Каталог перевода и правила локализации

Каталог локализации структурирован по модулям в папке `i18n/ru/`, а итоговый словарь собирается в `i18n/ru.json`:

```
i18n/
  ru.json                      # Итоговый скомпилированный каталог перевода
  ru/
    new-options.json           # Переводы названий и описаний настроек kOption...
    reviewed-settings.json     # Контекстно вычитанные настройки с жесткими условиями
    menus-and-search.json      # Контекстные меню, пункты поиска и системные токены
    reviewed-technical.json    # Реестр технических токенов, исключаемых из перевода
    title-presets.json         # Шаблоны заголовков и пресеты
```

### Привязка настроек к исходному коду

Для настроек перевод строго привязан одновременно к идентификатору опции (`kOption...`) и исходному английскому тексту (`source`):

```json
{
  "options": {
    "kOptionQuickView": {
      "name": {
        "source": "Open text files in tele",
        "translation": "Открывать текстовые файлы в tele"
      },
      "desc": {
        "source": "Open .txt, .json, .csv, and other code files directly in tele's code viewer.",
        "translation": "Открывать .txt, .json, .csv и файлы с кодом прямо во встроенном просмотрщике tele."
      }
    }
  }
}
```

Если upstream изменяет `source` (например, дополняет условия или меняет логику), перевод перестает совпадать и сборка требует вычитки нового текста.

### Правила глоссария и оформления

- **Терминологическое единство**:
  - «Отправка сообщений» — страница настроек `Sending` (включает не только отложенные сообщения).
  - «Отложенные сообщения» — блок `Scheduled messages`.
  - «Режим невидимки» — `Ghost mode`.
  - «Снимок сообщения» — `Message shot`.
  - «Студия подарков» — `Gift studio`.
  - «Коллекционные подарки» — `Collectible gifts`.
- **Сохранение параметров и плейсхолдеров**: Все переменные вида `%1`, `%2`, `%L1`, `%n`, `%%` и подстановки Qt должны оставаться на своих местах с сохранением контекста и грамматического порядка.
- **Форматирование кавычек**: В русском интерфейсе используются парные полиграфические кавычки «елочки» («…») и вложенные кавычки-лапки („…“).

### Множественные числа (плюрализация)

Русский язык требует трех форм множественного числа (1 настройка, 2 настройки, 5 настроек) вместо двух в английском (1 setting, 2 settings).
- На этапе наложения генерируется заголовочный файл `tele/tele_russian_plural.h` с инлайн-функцией `Tele::RussianPluralIndex(count)`.
- Вызовы склонения в коде tele автоматически адаптируются под правильные русские формы из словаря `plurals`.
- Целостность сгенерированного заголовочного файла проверяется unit-тестами с компиляцией и проверкой `static_assert`.

### Заголовки окна

- Шаблоны заголовков окна (`title-presets.json`) используют русский формат по умолчанию («Теле #{build}») и локализованные пресеты («{chat} – Теле», «Теле #{build} · {time:HH:mm}»).
- Наложение заменяет стандартный английский шаблон на «Теле #{build}», а вспомогательный модуль `tele_russian_title.h` (`Tele::RussianDefaultTitle`) динамически нормализует стандартные заголовки с учетом выбранного регистра («Теле #{build}» в обычном режиме и «теле #{build}» при включенном режиме строчных букв). Пользовательские кастомные шаблоны сохраняются без изменений.

## Подписанные обновления (Update Feed)

Клиент `teleru` оснащен механизмом фоновых самообновлений с криптографической защитой:

1. **Формат канала обновлений**:
   - Файл метаданных обновления (например, `teleru-update-win64.json`) содержит версию релиза, номер сборки, URL архива, SHA-256 хеш zip-архива и SHA-256 хеш исполняемого файла.
2. **Ed25519-подпись**:
   - Манифест обновления подписывается приватным ключом Ed25519 во время релизной сборки.
   - Публичный ключ (`ci/update-public-key.pem`) жестко встроен в исполняемый файл `tele`.
   - Клиент отклоняет любые обновления с отсутствующей или неверной подписью, несовпадающими контрольными суммами или ссылками со сторонних доменов.

## Локальная разработка и аудит

Для работы с проектом требуются **Python 3.11+**, **Node.js 18+** и **Git**.

### Пошаговые команды

1. **Проверка текущей версии upstream**:
   ```powershell
   python ci/upstream.py version
   ```

2. **Установка зависимостей CI**:
   ```powershell
   npm ci --prefix ci --ignore-scripts
   python -m pip install -r ci/requirements.txt
   ```

3. **Запуск автоматических тестов**:
   ```powershell
   python -m unittest discover -s ci/tests -v
   ```

4. **Применение upstream-патчей к чистому дереву Telegram Desktop**:
   ```powershell
   python ci/upstream.py apply --tdesktop C:\path\to\tdesktop
   ```

5. **Аудит и наложение русской локализации**:
   ```powershell
   python ci/localization.py C:\path\to\tdesktop
   python ci/translate_ru.py C:\path\to\tdesktop --inventory localization-inventory.json
   ```

Если аудит выявит пропущенные строки, файл `localization-report.json` покажет точные пути к исходным файлам, номера строк и оригинальный текст.
